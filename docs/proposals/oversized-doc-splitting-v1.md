> 状态:accepted(v2,吸收 2026-09-11 评审反馈后修订)
>
> 日期:2026-09-11
>
> 关联文档:`PROJECT-STATUS.md`;`.agents/tasks/04-workflow-runtime/walkthrough.md`、`.agents/tasks/04-workflow-runtime/README.md`;`docs/architecture/0001-cosmos-foundation.md`;扫描证据 [`docs/doc-governance/scan-2026-09-10.md`](../doc-governance/scan-2026-09-10.md);代码侧治理见 [`code-size-governance-v1.md`](code-size-governance-v1.md)
>
> 动机:开发者发现近期 token 消耗异常,怀疑查询文档时全量读入大文档所致。实测确认:349 KB 的 walkthrough.md 全量读入约 8.9 万~10.5 万 token。

## 1. 问题

全仓扫描(147 个 markdown 文档,2026-09-10)发现 9 个超过 50 KB 的文档,头部四个已构成实际成本:

- `.agents/tasks/04-workflow-runtime/walkthrough.md`:349 KB / 9055 行,109 个 Round 追加式记录。
- `.agents/tasks/04-workflow-runtime/README.md`:155 KB / 3467 行,几十个持续编号追加的 Spike 小节。
- `PROJECT-STATUS.md`:109 KB / 864 行,历史切片记录与「现状、风险、未完成边界」职责混杂,存在重复章节。
- `docs/architecture/0001-cosmos-foundation.md`:147 KB / 2506 行,22 章覆盖全部领域。

后果:agent 任何一次全量读入都会占掉 128k 上下文窗口的约 70%,并触发对话摘要压缩导致重读、消耗翻倍;人类也无法顺序阅读。仓库目前没有任何文档大小约束规则,追加型文档按设计无限增长。

v1 评审(2026-09-11)进一步指出 v1 草案的五个缺口,本修订逐项补齐:分册自身可能再超标(按编号范围切 89 个 Round 仍是 100 KB+)、字节阈值与 token 目标可能脱节(中文/表格密集时换算系数漂移)、只有定期扫描没有 CI 强制力、读取协议依赖 Agent 自觉、状态型混合文档(如 PROJECT-STATUS)没有专门拆法。

## 2. 目标与非目标

### 目标

1. 任何单个「活动」文档全量读入不超过健康区上限(≤9k token);归档分册同样受阈值约束。
2. 阈值同时约束字节与 token 估算,由 CI 强制执行,存量超标进基线只减不增,豁免显式登记。
3. 治理上述四个存量超标文档(由治理任务执行,G 系列编号见 `.agents/tasks/governance/README.md`)。

### 非目标

- 不改变任何代码行为,不引入外部文档系统或构建工具,全部走 git 普通文件。
- 不追溯清理 30–50 KB 区间且不增长的文档(进入基线观察即可)。
- `docs/requirements/0001-original-requirements.md` 按原话追加规则只增不减,不适用滚动归档;其豁免以 4.9 的豁免清单显式登记(首条豁免),不再以"体积健康"为由豁免。

## 3. 当前行为与证据

- 测量数据、待拆分与暂不拆清单见 [`docs/doc-governance/scan-2026-09-10.md`](../doc-governance/scan-2026-09-10.md)(已入库;`.agent/tmp/docs-to-split.md` 为临时副本)。
- token 换算实测:tiktoken 对 349 KB 文本统计为 89,314(o200k_base)/ 105,071(cl100k_base),即 **1 KB ≈ 255~300 token**;中文、代码块、表格密集文档的换算系数差异较大,因此阈值必须双轨(4.2)。
- 仓库现状:AGENTS.md 与 `.agents/tasks/AGENTS.md` 只规定文档职责和 walkthrough 持续更新,没有大小上限、归档和读取方式约束;walkthrough 越写越长是该机制的必然结果。

## 4. 方案(规范主体)

### 4.1 适用对象与文件类型

按文档生长方式分类,不按目录分类。三类拆分对象:追加型日志(walkthrough 的 Round 记录、状态文档的日期切片)、参考清单(DTO 清单、接口枚举、Spike 明细)、广域设计(单文档覆盖多领域的架构文档)。

适用文件类型:以 `.md`/`.mdx`/`.txt` 为主,扩展到 Agent 常读的其他文本类(`.json`/`.yaml`/`.csv` 等);生成型文档标记 `generated`,不手工拆。

不拆:单一主题内聚且定稿后冻结的文档(ADR、proposal、research)、按需查阅后返回的参考型清单(如 `docs/api/0003-product-dtos.md`)、入口索引页。

### 4.2 阈值:字节 + token 双轨,先到先触发

| 档位 | 字节 | token 估算 | 动作 |
| --- | --- | --- | --- |
| 健康区 | ≤ 30 KB | ≤ 9k | 不管;新增文档/分册必须落在本区 |
| 警戒区 | 30–50 KB | 9k–12k | 新增内容写入分册,主文档停止膨胀;处理优先级提前 |
| 红线 | > 50 KB 或 > 15k(先到先触发) | — | 必须拆,拆完主文档落回健康区 |

操作口径:红线 = 字节超 50 KB **或** token 超 15k,任一先到即触发;token 落在 12k~15k 且字节未超的灰区,按"接近红线"处理。token 估算优先使用真实分词器(如 tiktoken,可用时),否则按字符构成估算(ASCII/4 + CJK×1.1 的保守口径),扫描脚本同时输出字节、行数、token 估算三列。换算系数每季度抽样校准一次,中文密集文档占比升高时下调字节阈值。

### 4.3 拆分方法

- **追加型日志 → 按预算滚动归档**:主文档保留「当前状态 + 有效决定 + 最近的记录」,保留量以预算为准——保留到主文档接近 20~30 KB 即止,不采用固定轮数(固定 3~5 轮不可靠,记录长短差异大);有效决定较多时可单独沉淀 `decisions.md`。
- **参考清单 → 按域分册**:一个域一个文件,主文档只留使用说明和索引。
- **广域设计 → 按领域分册**:每章独立成册,主文档瘦身为索引 + 架构不变量 + 当前决定。

共同原则:沿文档已有结构边界切,不在一条记录中间切;**拆分是移动不是复制**,被移走的段落在主文档原位置替换为一行链接,避免两处内容漂移;拆分时同步修复所有交叉引用与锚点。

### 4.4 分册自身的大小约束(防"大文件变小分册")

- **单个分册 ≤ 30 KB,硬上限 50 KB**,与 4.2 阈值同轨(字节 + token 双看)。
- 按记录编号/日期切完仍超限的,继续下钻:按主题、按周、按 10~20 轮再切,直到落进上限。
- 文件名同时编码范围与规模约束,例如 `rounds-0001-0020.md`(约 20 轮一片,而非 89 轮一片);发现某个范围切出来仍超 50 KB,说明该粒度不可用,必须再切。
- 主文档的分册索引表本身设预算 **≤ 5 KB**:超限则把完整索引拆到同级 `index.md` 或 `index.json`,主文档头部只保留最近分册与分类入口。

### 4.5 状态型混合文档的专门拆法

`PROJECT-STATUS.md` 这类文档混合了「当前快照、活跃风险、未完成边界、历史切片」,不能整份当追加日志滚动归档——**滚动归档只切历史,不切当前状态和有效决定**:

```
PROJECT-STATUS.md            ← 当前快照 + 活跃风险 + 未完成边界 + 分册索引
PROJECT-STATUS/
└── history-2026-08.md       ← 按月切的历史切片记录
RISKS.md / BACKLOG.md        ← 可选:活跃风险或待办多到撑大主文档时才拆出
```

主文档开头必须是"当前快照"一节(一句话结论、当前阶段、下一步),保证 Agent 只读主文档即可获得现状。

### 4.6 目录组织

统一规则:分册放在主文档同目录下、以主文档名(去扩展名)命名的子文件夹内(示例见 4.5;架构文档同理为 `docs/architecture/0001-cosmos-foundation/05-persistence-runtime.md`)。理由:分册紧挨主文档,定位不用查第二处;删除整个 Task 目录时分册随之移除。备选的全仓集中式 `docs/archive/` 拒绝,理由不变。

### 4.7 存放、只读与勘误规则

- 分册定稿后只读:一个归档分册封口后不再修改,新记录写新分册,防止分册自身长成超大文档。
- **勘误不改历史分册**:原则上历史记录不修正;确需勘误时,在主文档的勘误小节或同级 `ERRATA.md` 追加勘误条目,注明指向的分册与位置。CI 或 CODEOWNERS 对归档子目录的修改做看护,防止无意改动。
- 文件名编码范围(`rounds-0001-0020.md`、`history-2026-08.md`),目录列表即目录。
- 每个分册头部带最小 front matter(供索引自动生成):`range`(覆盖范围)、`sealed_at`(封口日期)、`tags`(关键词)、`tokens`(估算)、`parent`(主文档路径)。仅分册强制,普通文档不强制。
- 全部为 git 仓库普通文件。

### 4.8 索引与导航

三层,从粗到细:

1. **文件名即索引**:范围编码在文件名里,目录列表一眼可定位。
2. **主文档头部放分册索引表**(≤5 KB,见 4.4):分册名 | 覆盖范围 | 标签 | 大小/token | 状态。
3. **Agent 读取协议**(治本措施,见 4.9 前置说明与工具层强制)。

索引由脚本根据分册 front matter 自动生成并用 CI 校验,避免手工维护漂移。

### 4.9 Agent 阅读协议与工具层强制

读取协议必须同时写入**根 `AGENTS.md`(全局,简版 ≤2 KB)** 和 `.agents/tasks/AGENTS.md`(Task 场景细化),不能只约束 Task 文档:

1. 先读根 `AGENTS.md` → 主文档头部的分册索引 → `rg` 定位关键词 → 只读命中分册的相关段落(offset/limit 局部读);
2. **禁止无理由直接读取 >30 KB 的文件**;确需全量读时,必须说明理由和 token 预算;
3. 若执行 Agent 不支持分段读取,则该场景下的分册必须 ≤ 健康区(≤30 KB 且 ≤9k token),保证全量读可接受——这是规范对工具能力的兜底,不依赖 Agent 自觉;
4. 禁读 node_modules、dist、.next、.worktree、锁文件、生成物、运行数据。

### 4.10 CI 门禁、基线与豁免

- **PR 检查**:红线 fail;警戒 warning;**新增文档不得进入警戒区**(必须落在健康区)。
- **存量超标进入 baseline,只减不增**:基线条目只允许删不允许加,基线内文件继续增大同样 fail。
- **豁免清单 `.docs-size-exemptions.yml`**(仓库根或 docs/doc-governance/ 下),每条含 `path`、`reason`、`owner`、`review_after`、`max_size`;首条即 `0001-original-requirements.md`(reason:append-only 原话真相源,规则内增长)。
- **脚本接口**:`size-governance.py --warn 30KB --fail 50KB --baseline <file> --fail-on-new`(文档类专用参数;退出码区分 fail/warn,供 CI 使用;原名 find-large-files.py,门禁化后更名)。
- **死链检查**:CI 对仓库内相对链接做存在性校验(自写脚本,lychee 可选),拆分后旧路径残留即报。
- **内容不丢失验证**:拆分 PR 必须附拆分前后比对——标题集合一致、代码块数量一致、列表项数量一致(脚本比对),证明"移动不是复制、也没有丢失"。

### 4.11 拆分任务模板与验收指标

每个存量文档拆分 Task 的 walkthrough 使用统一模板:

```markdown
## 拆分方案(治理任务 G{NN}:<目标文档>)
- 范围与现状:大小/行数/token 估算/章节结构
- 分册方案:切分粒度、分册清单与预估大小(每册 ≤30 KB)
- 主文档保留:当前状态、有效决定、最近记录、索引表
- 验证命令:扫描脚本 --check、死链检查、内容比对脚本
- 回滚方式:每册一个 commit,git revert
- 风险与交叉引用清单
```

验收清单:主文档 ≤30 KB;单分册 ≤30 KB;链接检查通过;扫描脚本通过;索引与 AGENTS 已更新;预估 token 下降比例写入 walkthrough。PR checklist 追加两行自检:是否触碰基线内文件;新增文档是否落在健康区。

## 5. 取舍与备选

| 备选 | 结论 |
| --- | --- |
| 分册按大小切(≤30 KB,超限下钻) | 采纳;按编号范围一刀切拒绝(v1 缺口:89 轮一片仍是 100 KB+) |
| 字节 + token 双阈值,先到先触发 | 采纳;只看字节拒绝(中文/表格密集时换算漂移) |
| CI 门禁 + baseline 只减不增 + 豁免清单 | 采纳;仅"定期扫描"拒绝(无强制力) |
| 读取协议入根 AGENTS.md + 工具层兜底(分册 ≤健康区) | 采纳;仅依赖 Agent 自觉拒绝 |
| 状态型混合文档只切历史 | 采纳;整份滚动归档拒绝(会切掉当前状态) |
| 主文档保留量按预算(接近 20~30 KB) | 采纳;固定 3~5 轮拒绝(记录长短差异大) |
| 索引脚本自动生成 + CI 校验,主索引 ≤5 KB | 采纳;手工索引拒绝(漂移) |
| front matter 仅分册强制最小集 | 采纳;全量文档强制拒绝(维护成本大于收益) |
| 扫描证据入库 docs/doc-governance/ | 采纳;留在 .agent/tmp 拒绝(评审与追溯不便) |
| 分册放主文档同名子文件夹 | 采纳(不变) |
| 引入外部文档平台 | 拒绝(保持 git 普通文件) |

## 6. 数据、接口、安全、迁移、发布与回滚影响

- **数据/接口/安全**:无 Prisma schema、无 migration、无 API 变更;纯文档与 Agent 约定。
- **迁移**:新增 `docs/doc-governance/`(扫描报告已入库;baseline 与 `.docs-size-exemptions.yml` 在 Task 实施时落地)、各主文档的同名分册子目录;`.agent/tmp/PROJECT-STATUS.pr2-registration.bak.md` 仍为清理候选。
- **发布**:不涉及版本号、发布或部署。
- **回滚**:git revert 即可;拆分只移动内容不删除信息。
