## 实现尝试与作废（2026-09-15）

**一句话**：信息架构决定（三层分工、对象页、Story 抽屉保留集）继续有效；配套实现在同日被判定布局有问题、回退并**作废**，UI 待维护者重新设计，**当前开发重心以功能为主**。

### 已作废的实现

2026-09-15 在分支 `feat/t25-ui-surface-ownership` 完成三个切片（话题页、Entity 页、「整理」页 + 主导航 + Story 抽屉瘦身），三层验证通过并合并到本地 `master`；维护者本地查看后判定布局有问题，当日回退，随后裁定该分支作废。分支与 worktree 保留但不再使用，其 ADR、Task walkthrough 与 spec 改动**都不进入 `master`**，重做时重新决定，不要当作既有合同。

### 维护者记录的 UI 问题（原话）

> 这版的布局有问题。

> 整体布局不合理，导航栏出现在页面下方，侧边栏消失不见，后续我会重新进行UI设计，不用着急。

性质判定（原话）：**「形状对，页面内部重排」**——形状不变，问题在页面内部排布与导航/侧栏位置；重做时不必再讨论「要不要回到抽屉方案」。

### 供重做参考的版面事实（Agent 从代码读出，「看起来如何」只在维护者本地被看过）

1. **主导航没有跨页面稳定位置**：首页把它放进侧栏容器，而该容器是页面第二行网格、上方还有页头与「信息库与搜索」区，所以首页导航落在页面中部偏下；三个对象页各在自己的页头里放一份。
2. **首页侧栏失去原有清单**：Entities 内联列表换成导航链接，侧栏视觉上像「空了/没了」。
3. **三个对象页没有侧栏**，从首页切过去会觉得侧栏消失。
4. **对象页统一「左列表 + 右详情」两栏**，宽屏比例、窄屏堆叠与断点都没专门设计，只是套了网格类。
5. **Story 抽屉只删了表单**、补了只读列表，没有重新设计剩余区块的顺序与分组。

### 暴露的两个流程问题（重做前先解决）

1. **版面骨架没被事先约定**：本 Proposal 冻结的是「哪个操作放到哪个页面」（信息架构），没有冻结导航与侧栏的跨页面位置、容器宽度与断点策略；这块实施时由 Agent 自行决定，结果导航位置违反使用习惯。→ 重做必须先冻结版面骨架，再动页面。
2. **门禁对版面零覆盖**：浏览器验收只断言「点得通、文字在、无横向溢出」，从未断言导航与侧栏**出现在哪里**，所以这类回归对门禁不可见——绿灯不代表版面正常。→ 重做时至少补：四个页面在 390px 与 1440px 下主导航都在首屏且位置一致；出现侧栏的页面断言其存在。

### 重做的前置条件

1. 维护者给出 UI 设计（至少含导航位置与侧栏策略），并把版面骨架写入稳定文档。
2. 补齐上面第 2 条的两类门禁断言。
3. 维护者解除「当前开发重心以功能为主」的顺序约束。
