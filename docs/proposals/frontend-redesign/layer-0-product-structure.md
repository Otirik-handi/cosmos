## 当前行为与证据（评审当时）

### 现状界面

- 首页 `apps/web/src/app/page.tsx`（802 行）是唯一的产品页面：页头 + 信息库与搜索区 + 左侧状态栏 + 看板 + 运行记录，全部堆在一个 `<main>` 里。Story / 话题 / Entity 都以抽屉形式盖在首页之上。
- 导航不存在：没有页面路由，没有全局导航元素。
- 侧栏是首页正文网格的第二行（`lg:grid-cols-[300px_minmax(0,1fr)]`），上面压着页头和搜索区——这正是「导航落在页面中部、切页后侧栏消失」的结构成因。
- 承载功能的组件已进入代码规模警戒区：`story-panel.tsx` 815 行、`board-view.tsx` 917 行、`collection-plan-list.tsx` 636 行、`registry.tsx` 614 行。
- UI 基础件只有 8 个（`components/ui/`）：badge、button、card、field、input、label、separator、textarea；无 dialog、无 dropdown menu、无 tabs、无 toast。

### 已具备的数据形状（`packages/contracts/src/`，当前真实合同）

`StoryDetail` 一次返回 `story`（含 `producer`、`timeRange`、`keyFacts`、`status`、`replacedBy`）、`entry`、`entries`、`entities`（含 `producer`/`confidence`/`evidence`/`actor`/`reason`）、`topics`、`labels`、`favorited`、`evidence`。Story 页几乎不需要额外取数，且**行内区分来源所需的字段全部现成**。

`LabelDetail` 自带 `assignedStories/Entries/Topics` 的解析后标题；`CollectionDetail` 自带 story 标题。

## 第 0 层 · 产品结构（维护者 2026-09-24 逐步裁定）

### P0 项目目标与边界

- **解决什么问题**：信息分散、消化成本高、功能堆积在一条 Story 上、文案过于专业化、版面无骨架。
- **给谁用**：沿用 PRD §3.1——愿意在个人电脑或私有环境自部署的重度信息用户（开发者、研究者、产品经理、创作者、跟踪行业动态的人）。
- **本次范围**：**重定版面骨架 + 重定视觉语言**。NeuroBook 主题与 macOS 明暗配色由「已冻结」降级为「待 V3 复审的候选」。
- **成功指标**：① 真人走一遍关键任务不迷路（不看说明即可完成）；② 版面门禁断言（四页导航位置一致 + 约定页面侧栏存在）。指标同时作为 V6 复审对照物与 I3 验收判据。

### P1 用户角色与核心场景

- **唯一交互角色是用户**。系统与 Agent 不作为独立角色界面出现。
- **但内容来源可见**：每条内容行内标出「来源采集 / 你手动创建的 / Agent 建议的」；另预留一个「系统产出」区，承载自动创建的 Story、采集运行结果，以及 Phase 3 的 Agent 产出。
- 依据：PRD §9 UC-07 第 4 条要求「UI 清楚区分同一事件成员、相关事件、Topic 成员和 Agent 推断」；该字段在 `StoryDetail.story.producer` 等位置已具备。

### P2 功能清单与优先级

| 能力 | 阶段 | 本次界面 |
| --- | --- | --- |
| 看板、搜索、Story、话题、Entity、用户组织、来源采集、连接、运行记录 | Phase 1–2 已交付 | **必做**（本次主体） |
| 看板拖拽排序 | 已定必做（Task 14 Follow-ups） | 纳入 |

| 推送、摘要图片、网页发布 | Phase 5 | 不做 |

### P3 竞品与参考分析

**跳过**。受众（重度信息用户）对同类工具已有稳定心智，无产品歧义需要外部输入解决。

### P4 信息架构设计

**八项主导航，内容 / 管理两组，侧边栏内分组、组内平铺直达、URL 层级 = 导航层级。**

```text
内容
├── 首页看板      /
├── 信息库        /library
├── 话题          /topics  /topics/:id
├── Entity        /entities  /entities/:id
└── 系统产出      /system
管理
├── 整理          /organize
├── 自动化        /automation
└── 设置          /settings

Story 深入          /stories/:id   （不占导航项）
```

- 「自动化」与「设置」分开，依据是 PRD §8.5 与 §8.6 本就是两节；合并会让「设置」成为 12 项杂货铺。
- 「系统产出」现在即有内容可填（自动创建的 Story + 运行记录），不必长期空置。
- 搜索条件进 query string，可刷新、可分享。

### P5 核心用户流程与状态清单

**主循环（每天）**：

```text
打开 Cosmos → 看板扫一眼 → 点开一条 Story → 读完 → 就地做一件事
                                              ├── 收藏 / 打标签 / 写批注 / 固定到看板
                                              └── 挂到已有话题 / 关联已有 Entity（选择器）
新建话题、新建 Entity → 只在话题页 / Entity 页（低频，跳转可接受）
```

**整理循环（每周）**：发现缺结构 → 去话题页 / Entity 页 / 整理页建对象 → 回内容。
**配置循环（低频）**：接一个新来源 → 试跑 → 看运行结果。

**「就地 vs 跳转」的归属规则**（与 D2 一致，未推翻）：**关联动作就地，创建动作去对象页**。Story 页可以挂到已有话题、关联已有 Entity、打标签、收藏、写批注、固定到看板；「新建话题」「新建 Entity」只在各自对象页。

**状态清单**（十项，P5 定清单、V2 定具体设计）：

| 状态 | 适用 |
| --- | --- |
| 加载 | 全部列表与详情 |
| 空 | 空库、空话题、空收藏夹、搜索无结果 |
| 部分 | 分页未完、媒体部分保存、多来源只取到一部分 |
| 错误 | 取数失败、命令失败 |
| 成功 | 写命令回执 |
| 禁用 | 前置条件不满足的按钮 |
| 权限不足 | **结构性不存在**（单用户最大权限），保留该项并标注 N/A，不设计 |
| 取消 | 长操作、表单放弃 |
| 重试 | 采集失败、探测失败、加载更多失败 |
| 边界情况 | 超长标题、无摘要、无 URL、无作者、历史壳、合并后别名 |

### P6 页面清单与页面结构

#### 版面骨架（本次核心产出，冻结后不得由实施自行变更）

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏（常驻，不滚动）                                                  │
│  Cosmos │ [全局搜索………………] │ 服务状态 · 系统产出 · 主题切换 · 新建  │
├────────────────┬─────────────────────────────────────────────────────┤
│ 左侧栏（常驻）  │ 主内容区（唯一滚动区）                              │
│  内容          │                                                     │
│   首页看板      │                                                     │
│   信息库        │                                                     │
│   话题          │                                                     │
│   Entity       │                                                     │
│   系统产出      │                                                     │
│  管理          │                                                     │
│   整理          │                                                     │
│   自动化        │                                                     │
│   设置          │                                                     │
└────────────────┴─────────────────────────────────────────────────────┘
```

- 顶栏与左侧栏是**跨页面常驻框架**，切页不重建；主内容区是唯一滚动区。
- 由此在结构上排除上次的三类缺陷：导航不可能落在页面下方（它在框架层，不在页面网格里）、侧栏不可能在切页时消失（跨页面常驻）、导航位置不可能随页面漂移（只有一处导航框架）。
- **唯一例外**：`/stories/:id` 隐藏左侧栏，保留顶栏，顶栏左侧变为「← 返回上一页」。理由：读一条内容的宽度优先，同时顶栏保证回程入口存在。该例外必须在门禁中有对应断言，避免被误判为回归。
- 顶栏搜索框输入后回车跳转 `/library?q=…`，完整筛选条件在信息库页展开；顶栏不放下拉结果面板。

#### 页面清单与区块

| 页面 | 区块 |
| --- | --- |
| `/` 首页看板 | 看板（区块类型：阅读流 / 热点 / 来源健康 / 话题列表 / 收藏夹）+ 系统产出区块 |
| `/library` 信息库 | 搜索表单（关键词 / 来源 / 时间区间 / 作者 / 媒体类型 / 录入状态 / 标签 / 话题）+ 当前条件 chips + 已保存视图（保存 / 套用 / 删除）+ 结果列表 + 加载更多 |
| `/topics`、`/topics/:id` | 列表（标题 + 关注目的 + 成员数）→ 详情：说明 + 成员表（角色 / 纳入理由 / 移除 / 恢复）+ 批注 |
| `/entities`、`/entities/:id` | 列表（名称 + 类型 + Story 数 + 关系数）→ 详情：别名 + 实体关系 + 关联 Story |
| `/system` 系统产出 | 自动创建的 Story（带「系统创建」标记）+ 采集运行结果 |
| `/organize` 整理 | 标签 / 收藏夹 / 收藏 / 批注 / 已保存视图 五分区（D6 一页内分区） |
| `/automation` 自动化 | 来源 + 采集计划 + 连接 + 运行记录 |
| `/settings` 设置 | Data Root / 存储 / 媒体保留 / 备份导出 |
| `/stories/:id` | 正文 + 来源成员（标出采集 / 人工）+ 时间线 + 关键事实 + 引用关系 + 相关内容 + 读完动作区 + 归并拆分 + 用户状态迁移 |

**首页形态**：整套检索工作台搬到 `/library`，首页为纯看板 + 系统产出区块，不再是「看板 + 列表」的混合页。依据：看板的「阅读流」区块类型已能承载按条件浏览。
