## 2026-08-06：第一轮需求和能力

> 接下来你作为一位专业的架构师进行架构设计，架构要灵活可扩展。
> 接下我来提出需求和能力。你来来你进行架构设计和调整。接下来我要提出第一次的需求和能力了。先建立 cosmos 仓库。设计好了后把架构输出到一个文件中，我的原始需求也记录到一个文件中（防止失真），后续几轮可以在此文件基础上调整。
>
> 1. 关于 Source，是否类似 github 的 action，既能用户手动触发，也能定时触发，也能自定义触发器（例如轮询检测邮箱，如果有新邮件则触发）。关于触发后应该执行的代码也是可以自定义的，甚至可以跑 agent。
> 2. RawObservation.url 这个字段，你需要考虑类似：消息来源于 Telegram、公众号、群聊这种。没有 url 的。
> 3. 系统应该是要维护一个信息库，这个信息库的原则是尽可能收集更多用户关注领域的信息。也就是说这个项目是信息聚合平台，用户不用亲自去花费时间去各个平台浏览。项目先去各个渠道收集信息（这可以使用各个平台的推荐系统 + 搜索系统），对应于用户自己操作的随意浏览阶段（项目相比用户自己来做，它能浏览更多信息，深度也更广，自定义程度也更高）。这是第一阶段，原始信息录入（把多个渠道的消息聚合，也就是信息录入后，本地项目离线也能访问已经录入的信息。需要存图片，这里我可以放宽为：“尽可能”）。信息库需要设计得非常灵活便于查询，分类、便签、BM5 这方面你可以考虑一下。
> 4. 经过第一阶段，信息库中存的一般都是与用户设定的注意比较相关的信息。对于这些信息，他们可能是这样的：
>    - 用户 BiliBili、X 等平台账号的主页推荐（可能每个小时就录入一批）
>    - 用户 BiliBili、X 等平台账号的关注用户（频率可能高一点）
>    - 某个网站的公告（靠触发器轮询）
>    - AIHOT 网站（去要去重）
>    - 邮件消息
> 5. 接下来就是考虑如何把这些信息展示给用户了。我觉得这个应用把消息展示给用户有两种：第一种是看板，另一种是推送。
>    - 看板需要展示：当前热点（热点可以是系统设置的，例如：DeepSeek API 状态追踪，或者是用户设置的，例如：XX 大会），精华消息（系统Agent精选过的信息，cosmos agent 通常会对这些主体进行深入。并且可以生成可视化的页面。例如：某一篇技术博客：LLM 先读一遍然后可以给出批注和观点。例如Agent 在信息库中发现了某一个竞品项目，自主进行深入调研产出报告。）。其他信息流（推荐系统，这一部分通常不用 LLM 参与。）总之看板界面的自定义程度很高
>    - 推送：考虑 Telegram、邮箱场景。目前先专注看板把。这个推送通常用于紧急消息、热点的推送
> 6. 目前系统中存在的实体：原始信息，话题（包含多个原始信息），精华（包含多个原始信息和多个话题，同时还带文件、附件、和可视化页面（数据形态可以给一个文件夹））（热点应该算精华的一种）（我觉得这些名字可能有点不太恰当）
>

> 我期待的使用场景，举例：
>
> 1. 早上八点向 QQ、Telegram、Email 等渠道推送一版摘要（形态可以是渲染出来的图片，并附上一份网页链接，点击直接进入软件的看板界面）
> 2. 点开看板（下面这两个属于热点主体，肯定有同类的信源。不同的信肯定能让我们更全面的看待一件事物。点进去还可以看到相关联的信息，例如：《本地部署 Qwen-Image-3.0-Pro 教程》，属于推荐系统的部分了）：
>    - 字节 Seed 发布 SeedRealtime 音视频全双工大模型字节 Seed 发布 SeedRealtime 音视频全双工大模型

> 4. 精华下面就是消息流，可以用户分类、分区（娱乐，硬件、开发等）浏览。走推荐系统
