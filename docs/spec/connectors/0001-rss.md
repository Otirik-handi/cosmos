## 组件定位

该插件提供三种 `IngestConnector` 实现形式：

- RSS/Atom 连接器（`rssConnector`），连接器标识常量 `rssConnectorId` 的值为 `rss`，通过 HTTP 获取并解析 RSS 或 Atom XML。
- fixture RSS 连接器（`fixtureRssConnector`），连接器标识常量 `fixtureRssConnectorId` 的值为 `fixture-rss`，从本地文件或注入的单页内容读取 XML。
- 序列 fixture 连接器（`createSequenceFixtureConnector`），使用 `fixture-rss` 标识，在内存中按调用次数选择预置 XML 页面，主要用于确定性的运行时测试。

三者负责取得 XML、解析条目并标准化返回，不直接创建或持久化领域记录。


### 在系统中的位置与作用
它是插件层的 RSS/Atom、fixture RSS 和序列 fixture `IngestConnector`，位于 Connector runtime 与 RSS/XML 来源之间。

### 解决的问题
它负责取得完整 XML、解析 RSS/Atom 条目并调用 domain 标准化，向上提供统一的分页 item 与 cursor，而不直接写领域数据库。

### 使用方式
把 `rss` 或 `fixture-rss` connector 注册到 `ConnectorRegistry`；runtime 先调用 `validate(source)`，再调用 `fetchItems`，checkpoint 游标由 ingest workflow/application 管理。

### 典型情景
接入一个 RSS/Atom 来源、用本地 XML fixture 验证解析，或用序列 fixture 构造确定性的分页/重试测试时，选择对应实现。

## 概念与定义

共享契约以 [Source](../contracts/0001-public-contracts.md) 和 [NormalizedIngestItem](../domain/0001-normalized-content.md) 的 owner 文档为准；连接器调用以 [Connector](../application/0001-connector-runtime.md) 为准，[Checkpoint](../application/0006-ingest-workflow.md) 的游标语义由 Workflow owner 规定。领域值以 [Publisher](../domain/0001-normalized-content.md)、[TemporalValue](../domain/0001-normalized-content.md)、[Asset](../domain/0001-normalized-content.md) 和 [Blob](../storage/0005-file-blob-store.md) 的 owner 文档为准，本文不重复这些共享类型的定义。

“完整 XML”指某次 `fetchItems` 实际读取或选中的整个 XML 字符串，而不是单个 `item` 或 `entry` 片段。“FNV 风格 hash”指实现中的非加密 32 位字符串散列及其十六进制结果，不表示远端服务提供的分页位置。

## 外部行为

所有实现都遵循 `IngestConnector` 的调用形态：`validate(source)` 用于校验可执行条件；`fetchItems({ source, cursor, idempotencyKey?, signal? })` 使用对象参数并返回 `items` 与 `nextCursor`。连接器不直接持久化领域数据。

网络 RSS/Atom 连接器的 `validate(source)` 只检查 `source.config.feedUrl` 是否 truthy；缺失或 falsy 时校验失败。它不执行 URL 格式、协议或可达性 strict 校验；这类 URL strict 校验由上游 contracts/API owner 负责。`fetchItems` 使用构造时注入的 `fetch`，未注入时使用 `globalThis.fetch`，并把收到的 `AbortSignal` 传给该调用。连接器自身不设置超时。

XML 解析只识别 `rss.channel.item` 与 `feed.entry`。两处节点都可以是单个对象或数组，并被统一为条目序列。每个条目按以下规则标准化：

- 标题取 `title`，缺失时使用 `Untitled RSS item`。
- 正文依次取 `content:encoded`、`description`、`content`、`title`；选中的文本会移除标签并压缩空白。
- 外部标识依次取 `guid`、`id`，均不存在时为 `null`。
- 主发布时间依次取 `pubDate`、`published`、`updated`；更新时间取 `updated`。
- 时间值交给 `createTemporalValue`；可解析的输入得到 exact 值，不可解析但有原文时得到 fallback，缺失时为 `null`；解析调用的 timezone 参数为 `UTC`。
- 作者依次取 `author`、`creator`、`dc:creator`，存在时交给 `normalizePublisher`；不存在或没有可用名称时 publisher 为 `null`，存在有效名称时其 kind 为 `unknown`。
- RSS 链接可以是字符串；Atom 链接可以是数组，优先选择 `rel=alternate`，否则选择第一项，并从 Atom 链接的 `href` 取 URL。
- 条目的 kind 固定为 `article`。
- 网络来源的 source locator 合并 provider `rss`、`feedUrl` 与条目的 externalId；fixture 来源合并 provider `fixture-rss`、`fixturePath` 与 externalId。
- `enclosure` 只生成 kind 为 `enclosure`、状态为 `metadata_only` 的资源元数据，保留 `url`、`type`、`length`，其 content 为 `null`。
- 每个产出项的 raw payload 都是该次获取的完整 XML，MIME 类型为 `application/xml`。

`nextCursor` 是对完整 XML 计算得到的非加密 32 位 FNV 风格十六进制 hash。空字符串也会计算 hash。它不是服务端分页游标，传入的 `cursor` 不参与网络请求或单页 fixture 的内容选择。

fixture RSS 连接器默认相对于 `rootDirectory` 读取 `fixtures/rss/basic.xml`；`rootDirectory` 默认是 `process.cwd()`。`source.config.fixturePath` 可以覆盖默认路径，绝对路径直接使用，相对路径相对于 `rootDirectory` 解析。创建连接器时若提供 `pages` 选项，则使用 `pages[0]` 作为本次 XML，而不读取文件。

序列 fixture 连接器只使用创建时给定的内存 `pages`。内部 `pageIndex` 从 `0` 开始随调用递增；索引超出范围后继续选择最后一页。其 `validate` 不执行校验，`fetchItems` 忽略传入的 `source`、`cursor` 和 `signal`。每页仍通过同一标准化逻辑生成条目、完整 XML raw payload 和 hash cursor，source locator 使用 provider `fixture-rss` 与 fixturePath `memory://fixture`。

## 输入

网络 RSS/Atom 连接器从 `source.config.feedUrl` 取得请求地址，并接收对象形式的 `fetchItems({ source, cursor, idempotencyKey?, signal? })` 调用参数。只有 `feedUrl` 的 truthy 条件由该连接器的 `validate(source)` 明确检查；URL strict 校验不在插件内执行，而由上游 contracts/API owner 负责。

fixture RSS 连接器从创建选项中的 `rootDirectory`、可选 `pages`，以及 `source.config.fixturePath` 决定 XML 来源。相对路径必须按 `rootDirectory` 解析。

序列 fixture 连接器的有效内容输入是创建时传入的 XML 页面数组；每次调用参数不影响页面选择。

## 输出

成功的 `fetchItems` 返回：

- `items`：由 `rss.channel.item` 和 `feed.entry` 标准化得到的条目数组。
- `nextCursor`：本次完整 XML 的 32 位 FNV 风格十六进制 hash。

同一次获取产生的所有条目共享相同的完整 XML raw payload 和相同的 `nextCursor` 计算输入。没有 enclosure 的条目不因该字段产生资源元数据；有 enclosure 的条目也只返回 `metadata_only` 元数据，不包含下载内容。

## 状态与持久化

网络 RSS/Atom 连接器和单页 fixture RSS 连接器不维护持久分页状态。序列 fixture 连接器仅在当前 JavaScript 实例内维护 `pageIndex`；重新创建实例会从 `0` 开始，该状态不持久化，也不由传入 cursor 恢复。

Application/Worker 通过 repository/workflow 端口负责持久化 [Checkpoint](../application/0006-ingest-workflow.md)、[Observation](../domain/0001-normalized-content.md)、[Entry](../domain/0001-normalized-content.md)、[Revision](../domain/0001-normalized-content.md) 和 [Asset](../domain/0001-normalized-content.md)；raw payload 仍先作为返回 item 中的字符串，后续由 storage 按 [File Blob Store](../storage/0005-file-blob-store.md) 合同写入受控 Blob。RSS 插件本身不执行 Blob 写入，`metadata_only` enclosure 不触发内容下载。

## 状态转换

网络 RSS/Atom 连接器在校验成功后，每次获取都独立执行 HTTP 请求、读取完整响应文本、解析和标准化，并由该文本计算新的 `nextCursor`。传入 cursor 不改变请求。

fixture RSS 连接器每次调用重新选择 `pages[0]` 或解析目标文件，之后按完整 XML 生成条目和 cursor，不保留上次调用状态。

序列 fixture 连接器在第 `n` 次调用时选择 `pages[min(pageIndex, pages.length - 1)]`，随后使 `pageIndex` 递增。达到最后一页后，后续调用持续返回最后一页；cursor 仍由实际选中的 XML 计算，而不是由 `pageIndex` 生成。

## 副作用

网络 RSS/Atom 连接器执行一次 HTTP fetch，并传播调用方的取消信号。fixture RSS 连接器在未提供 `pages` 时读取本地文件。序列 fixture 连接器修改实例内的 `pageIndex`。

实现会记录脱敏日志。成功路径包含 `responseBytes`、标准化条目数量和耗时等诊断信息；失败日志不得写入 XML 或 HTTP 响应正文。非 2xx 响应的日志只保留状态码和 feed URL 的 host 等必要诊断字段。插件不写领域存储、不写 Blob，也不下载 enclosure。

## 错误与降级

网络响应为非 2xx 时：

- HTTP 429 映射为 `rate_limited`，`retryable=true`。
- 其他非 2xx 映射为 `dependency_unavailable`。
- 只有 5xx 或 429 标记为可重试；其余非 2xx 不标记为可重试。
- 错误处理不读取、记录或附带响应正文，日志仅记录状态码、host 等脱敏信息。

`response.text()` 失败或 XML 解析失败映射为 `malformed_payload`，并记录脱敏后的 `responseBytes`、条目数量、耗时或可获得的错误上下文，不记录完整响应正文。

HTTP fetch 或网络层抛出的错误若不是 `ConnectorExecutionError`，可原样越过连接器边界，由上层运行时归类为 `dependency_unavailable` 且可重试。`validate` 抛出的普通 `Error` 由上层归类为 `invalid_configuration`。

fixture 的文件读取和解析错误没有被统一改写：实现会按 `malformed_payload` 记录错误，但原始错误可能继续透出；若捕获到的错误已经是 `ConnectorExecutionError`，则保留该错误。本文不把这种差异扩展为统一错误协议。

## 依赖

实现依赖 `IngestConnector` 及相关公共契约、领域标准化辅助函数 `normalizePublisher` 与 `createTemporalValue`、XML parser、注入的 Fetch API 或 `globalThis.fetch`、Node.js 文件与路径能力，以及运行时提供的日志和错误归类机制。

fixture 默认路径还依赖 `process.cwd()`；调用环境的工作目录会影响未显式设置 `rootDirectory` 时实际读取的位置。

## 重建验收

1. 导出的 `rssConnectorId` 必须严格等于 `rss`，`fixtureRssConnectorId` 必须严格等于 `fixture-rss`。
2. 对缺失、空或其他 falsy `source.config.feedUrl` 调用网络连接器 `validate` 必须失败；truthy 值必须通过该项检查。
3. 注入 fetch 时必须调用注入实现；未注入时必须调用 `globalThis.fetch`；传入的 `signal` 必须是 fetch 使用的信号，连接器不得自行创建超时。
4. 对 429 响应必须得到 `rate_limited` 且可重试；对 500 至 599 响应必须得到 `dependency_unavailable` 且可重试；对其他非 2xx 响应必须得到 `dependency_unavailable` 且不可重试。
5. 非 2xx 诊断日志必须可检查到状态码和 host，且错误、日志和返回值中均不得出现响应正文。
6. `response.text()` 拒绝或 XML parser 抛错时必须得到 `malformed_payload`；日志不得包含完整 XML。
7. RSS 单个 `item`、RSS `item` 数组、Atom 单个 `entry` 和 Atom `entry` 数组必须都能转成条目数组，并严格遵守标题、正文、标识、时间、作者和链接优先级。
8. 无标题条目必须输出 `Untitled RSS item`；正文必须移除标签并压缩空白；输出 kind 必须为 `article`。
9. 网络、文件 fixture 和内存 sequence 的 source locator 必须分别使用 `rss/feedUrl`、`fixture-rss/fixturePath` 和 `fixture-rss/memory://fixture`，并合并条目的 externalId。
10. enclosure 必须只产生 `metadata_only` 元数据，保留 `url`、`type`、`length`，content 必须为 `null`，且不得发生附件下载。
11. 每个条目的 raw payload 必须是完整 XML且 MIME 为 `application/xml`；`nextCursor` 必须等于该 XML 的实现内 32 位 FNV 风格十六进制 hash，空 XML 也必须产生 hash。
12. fixture 在未提供 `pages` 时必须按 rootDirectory 和 fixturePath 规则读取文件；提供 `pages` 时必须使用 `pages[0]`。
13. 序列 fixture 第一次调用必须使用第 0 页，后续调用依次前进，越过末页后必须重复末页；其结果不得受传入 source、cursor 或 signal 影响。
14. 连接器执行期间不得出现领域记录或 Blob 写入；raw payload 的受控 Blob 写入必须发生在 Application 和 storage 的后续持久化阶段。
15. fixture 普通读取错误允许原样透出但必须记录 `malformed_payload`；已有 `ConnectorExecutionError` 必须保持原错误。

## 非目标/边界

本文不定义 Application 的调度、重试策略或领域持久化细节，只说明连接器与这些职责的边界。插件不负责创建 Observation、Entry、Revision，不负责持久化 Checkpoint、Asset 或 Blob，也不下载 enclosure 内容。

解析范围限于实现实际读取的 `rss.channel.item` 和 `feed.entry` 结构；fixture 中的三项数据不得推广为对所有 RSS、Atom 扩展或命名空间的承诺。

当前测试没有验证真实网络 RSS 源、RSSHub、真实 Atom 来源或长时间运行后的恢复行为。网络取消只保证传递调用方的 `AbortSignal`；连接器自身没有超时机制。序列 fixture 的 `pageIndex` 仅是实例内测试状态，不具备跨进程恢复含义。
