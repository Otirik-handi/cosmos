## Round 5（2026-10-03）：分隔线统一成 `<Separator>`，并修掉两处错的

### 本轮切片与本轮订正

维护者问「为什么分割不用 divider 组件」，Agent 答完后实测发现**自己上一条回答里有两处说错了**，
维护者据此裁定：**全仓 38 处统一改用 `<Separator>`、接受 40 px、包装成装饰性**。本轮做这件事。

**订正一（颜色）**：Agent 曾说「线用的是 `--border` token，`Separator` 用的是它自己的颜色」。
实测（`.agent/tmp/t36-divider-color-probe.ts`）**是反的**：`border-t` 没带颜色类时，
Tailwind v4 预检让它继承 `currentColor`，实测 `borderTopColor: rgb(28, 31, 28)`＝**正文墨色**；
而 `Separator` 的 `bg-border` 是 token 的 `#e6e4dc`。**也就是所有分隔线一直偏重**。

**订正二（两栏机制）**：Agent 曾说两栏都有「分隔线 + 间距」两级。实际情况是**只有右栏有分隔线**；
左栏（成员 / 证据 / 时间线 / 相关内容 / 媒体）**没有线**，只有 `gap-6` 的 24 px 间距。

### 实施

| 文件 | 改动 |
| --- | --- |
| `components/ui/separator.tsx` | 加 `decorative` 开关（装饰性，从无障碍树摘掉）；**修掉变体属性名**（见下「真缺陷」）；补 `data-orientation` |
| `story-edit-panel.tsx` | 5 处分隔：标题行下 1、三大块之间 3、错误行上 1 |
| `story-panel/` 8 个文件 | `border-t pt-4` / `border-b pb-4` 全部换成块与块之间的 `<Separator decorative />`；`story-actions` 的改表示内部再加 2 处 |
| `story-edit/organization-editor.tsx` | 三段之间加 2 处 |
| `topic-panel.tsx` / `entity-panel.tsx` | 页头 `border-b` → 分隔元素；区块 `border-b pb-4` → 分隔元素；`border-t pt-4` → 分隔元素 |
| `board-view/editor.tsx`、`lab-inspector`、`lab-stage`、`workbench` | 各自 1 处，全部换成分隔元素 |
| `components/ui/card.tsx` | `CardFooter` 的 `border-t` 补 `border-border`（它是圆角 footer 的收口线，不适合塞子元素，按颜色修正处理） |

**保留 `border` 写法的三类**（其余全改）：

1. **列表行**：`... border-t py-3 first:border-t-0`（成员行、Entity 行、Topic 成员行、看板区块行）——
   行间线依赖 `first:` / `last:` 变体，独立元素表达不了「第一行不要线」，且这些行已经写了 `border-border`。
2. **`CardFooter` / `DialogFooter` 的收口线**：圆角容器的一部分，不只是分隔。
3. **`Tabs` 的 `border-b`**：它同时是「选中态下划线」的基线，属控件几何而非版面分隔。

### 真缺陷：`Separator` 此前渲染出来是**看不见的**

迁移后实测（`.agent/tmp/t36-separator-probe.ts`）发现**分隔线高度是 0 px**。根因：
primitive 的变体写成 `data-horizontal:h-px data-vertical:w-px`（Tailwind v3 / Base UI v1 的名字），
而仓库装的是 Base UI v2，它只输出 **`data-orientation`**（
`@base-ui/react/separator/SeparatorDataAttributes`）。两条宽度规则都不命中 → 没有高度。

改用 `data-[orientation=horizontal]:…` 并显式补 `data-orientation` 后，实测横向 `h=1px`、
竖向（实验室 `scene=vertical`）`h=48px`（`h-12` 覆盖）均正确。
**这个缺陷此前没暴露，是因为业务代码从来没渲染过这个组件**——本轮是它的第一个消费者。

## Round 6（2026-10-03）：分隔线粗细改成 0.5em，并修实验室的演示

### 本轮切片

维护者看完实验室后反馈「你这个分割组件样式不行」，两次追问后给出具体诉求：

> 分割线太细了，可以粗一点，试试0.5em

Agent 先出了两张对比图确认取值（`.agent/tmp/t36-divider-options.png` 五档颜色、
`.agent/tmp/t36-divider-thickness.png` 五档粗细含真实右栏 250 px 预览），维护者选定 **0.5em**。

### 实施

| 文件 | 改动 |
| --- | --- |
| `app/globals.css` | 新增第 3 层 token `--divider-thickness: 0.5em`（用 em 不用 px：线的重量跟着区域字号走，与 V4 两套密度一致） |
| `components/ui/separator.tsx` | 横向线 `h-px` → `h-[var(--divider-thickness)]`；**竖向线保持 `w-px`** |
| `component-lab/tokens.ts` + `registry/shared.ts` | 登记 `--divider-thickness`（kind `length`），实验室里可调 |
| `component-lab/registry/ui-renderers.tsx` | 横向场景从「一根 `max-w-md` 短横线」改成**整宽 + 上下配文字**：原来 448 px 的短线段看不出真实宽度与重量，这是「实验室里样式看着不行」的一半原因 |

**竖向线不复用这个 token**：同一条 0.5em 套在竖向上会变成 8 px 宽的竖条而不是分隔线，属版式事故。
竖向仍是 1 px，实验室里 `scene=vertical` 可对照。

### 偏差（Round 6）

- **0.5em 是一条色带，不是发丝线**：16 px 字号下 8 px 高，视觉重量明显高于 `border`。
  这是维护者选定值，不是 Agent 的判断；Agent 已提供 1/2/4/6/8 px 对比图。
  代价是面板里「区块归属」的提示更强、留白感被压缩（实测间距不变，仍是 20/16 px）。
- **实验室的演示此前只画一根 448 px 短横线**，与实际用途（整宽分隔两个区块）不符，
  Round 6 一并改成整宽并配上下文文字。
